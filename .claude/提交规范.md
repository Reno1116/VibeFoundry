# Git 提交规范

Agent 在完成一个模块后，**必须先获得用户同意**，再按本规范提交代码。

## 提交格式

### 标题（必须）

```text
[阶段][动作](工具名) 具体结果
```

| 部分 | 格式 | 说明 |
|------|------|------|
| 阶段 | `design` / `dev` / `repo` | 当前工作属于哪个阶段 |
| 动作 | 见下方动作表 | 本次改动的性质 |
| 工具名 | 英文短名，可省略 | `projects/` 下的目录名；仓库级改动可省略 |
| 具体结果 | 中文短语，15 字以内 | 一句话说清做了什么 |

### 正文（必须）

```text
- 改动内容：具体改了哪些文件、模块或逻辑
- 验证方式：如何确认改动正确（测试、手动验证、截图对比等）
- 后续事项：还需做什么（无则写"无"）
```

### 示例

```text
[dev][新增](jenkins-launcher) 完成 API 请求模块

- 改动内容：新增 src/api.py，封装 Jenkins REST API 的构建触发与状态查询；处理超时与证书验证
- 验证方式：用本地 Jenkins 实例测试了参数化构建触发，返回 201 且队列 ID 正确
- 后续事项：接入前端触发按钮与参数表单
```

```text
[dev][修复](file-organizer) 修复批量重命名时中文乱码

- 改动内容：src/rename.py 第 42 行 encode 参数从 'gbk' 改为 'utf-8'
- 验证方式：用 50 个中文文件名批量测试，重命名结果全部正确
- 后续事项：无
```

```text
[repo][整理] 简化提交规范并更新 CLAUDE.md

- 改动内容：新增 .claude/提交规范.md；更新 CLAUDE.md 引用
- 验证方式：通读文档确认无矛盾
- 后续事项：无
```

## 动作定义

### 开发阶段（dev）

| 动作 | 使用场景 | 示例 |
|------|---------|------|
| `新增` | 新增文件、模块、功能点；完成一个独立模块 | `[dev][新增](工具名) 完成日志记录模块` |
| `修改` | 改动已有功能的行为或逻辑（非 bug 修复） | `[dev][修改](工具名) 调整配置文件读取路径` |
| `修复` | 修复 bug、崩溃、异常行为 | `[dev][修复](工具名) 修复空输入时的崩溃` |
| `调优` | 性能优化、体验改善、文案调整 | `[dev][调优](工具名) 优化大文件扫描速度` |
| `重构` | 重写内部实现，不改变对外行为 | `[dev][重构](工具名) 抽取公共验证逻辑` |

### 设计阶段（design）

| 动作 | 使用场景 | 示例 |
|------|---------|------|
| `新增` | 新建设计文档 | `[design][新增](工具名) 新增需求与交互设计` |
| `修改` | 更新设计内容 | `[design][修改](工具名) 调整核心流程与状态设计` |
| `确认` | 设计经人工确认，标记为已确认 | `[design][确认](工具名) 确认设计文档与 Figma 交互` |

### 仓库级别（repo）

| 动作 | 使用场景 | 示例 |
|------|---------|------|
| `新增` | 新增仓库级别的配置或文档 | `[repo][新增] 添加提交规范文档` |
| `修改` | 修改仓库配置或约定 | `[repo][修改] 更新 .gitignore 规则` |
| `整理` | 结构调整、文件移动、清理 | `[repo][整理] 简化仓库结构` |
| `删除` | 删除不再需要的文件 | `[repo][删除] 移除废弃的模板文件` |

## 提交时机与审批规则

### Agent 必须遵守

1. **模块完成后才能提议提交** — 一个独立的功能、修复或结构调整完成并验证通过后，主动告知用户可提交
2. **提交前必须获得用户同意** — 使用 `AskUserQuestion` 或对话确认，绝不在用户不知情时执行 `git commit`
3. **一次提交只做一件事** — 不把新增功能和结构调整混在同一 commit
4. **改动超过 5 个文件或跨 2 个以上模块时，拆分提交** — 保持每个 commit 可独立理解、可独立回滚
5. **正文必须写清楚** — 改动内容、验证方式、后续事项缺一不可

### 用户审批流程

```
Agent 完成模块 → Agent 列出改动摘要 + 建议的提交信息 →
用户审阅确认 → Agent 执行 git commit
```

### 不建议提交的情况

- 改动未验证
- 工作只完成一半（WIP）
- 包含调试代码或临时文件
- 混合了无关改动（先拆开再分别提交）

## 工具名速查

工具名取 `projects/<工具名>/` 中的目录名，与目录名完全一致：

| 工具目录 | commit 中的工具名 |
|---------|-----------------|
| `projects/jenkins-build-launcher/` | `jenkins-build-launcher` |
| `projects/file-organizer/` | `file-organizer` |

仓库级别改动（修改 `.claude/`、`README.md`、`.gitignore` 等）不加工具名。
