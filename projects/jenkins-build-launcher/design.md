# Jenkins 构建启动器

> 当前处于需求与交互确认阶段；人工确认前不进入代码开发。

## 基本信息

- 工具名称：Jenkins 构建启动器
- 一句话说明：根据 Git 提交哈希解析分支与提交信息，确认后用三个参数一键触发 Jenkins 构建。

## 需求

- 使用者：能访问本地 Git 仓库与目标 Jenkins Job 的内部开发、策划或构建人员。
- 当前问题：构建前需要分别查找并复制代码分支、策划文档分支和提交信息，再进入 Jenkins 手工填写，步骤重复且容易选错分支或漏填内容。
- 期望结果：粘贴 Git 提交哈希后，工具自动解析可验证的信息，填入三个可编辑参数；用户确认一次即可触发构建，并能打开 Jenkins 队列或构建详情。
- 成功标准：
  - 合法提交能解析为完整 SHA、提交信息和当前可见的远端分支候选。
  - 唯一且可信的分支自动填入；多候选、未推送或无法映射时明确提示用户选择，不静默猜测。
  - 代码分支、策划文档分支、提交信息在触发前始终可修改。
  - 单击一次只创建一次 Jenkins 构建；接口接受后展示队列链接，取得构建编号后展示构建详情链接。
  - Jenkins 凭据不写入仓库、普通配置或日志。

## 本次范围

- 要做：
  - 首次配置代码仓库、策划文档仓库、Jenkins Job 地址、三个参数名和认证信息。
  - 输入代码提交哈希；当策划仓库独立且无映射规则时，支持补充策划提交哈希或手选策划分支。
  - 校验提交、解析完整 SHA、读取提交信息、查找包含该提交的本地/远端分支候选，并校验提交是否已推送。
  - 自动填充并允许修改代码分支、策划文档分支、提交信息。
  - 通过 Jenkins 参数化构建接口触发一次构建，展示排队、运行、成功或失败反馈，并可打开 Jenkins 页面。
- 不做：
  - 不修改 Jenkins Pipeline 或仓库分支。
  - 不在没有规则的情况下，从一个仓库的提交哈希猜测另一个仓库的分支。
  - 不做通用 Jenkins 管理台、构建历史管理或批量构建。
  - 第一版不依赖浏览器页面元素定位来自动填表。
- 平台与限制：
  - 目标为 Windows 本地工具，只监听 `127.0.0.1`，通过本机 Git 读取仓库信息。
  - Jenkins 应提供参数化构建 API；凭据优先存入 Windows Credential Manager，使用目标 Job 的最小权限账号。
  - Git 提交对象不记录来源分支；分支只能根据当前可见 refs 推导，结果可能为零个、一个或多个候选。
  - 为避免分支继续前进导致构建内容变化，建议 Jenkins 同时接收代码/策划完整 SHA，并按 SHA checkout；是否能调整 Job 参数待确认。
- 已有代码、数据或参考资料：当前仓库没有既有工具代码；代码仓库路径、策划仓库路径、Jenkins Job URL、实际参数名和认证方式待提供。

## 核心流程

1. 用户首次完成本地仓库与 Jenkins Job 配置，进入“新建构建”。
2. 用户粘贴代码提交哈希；若策划文档来自独立仓库且没有可靠映射规则，再粘贴策划提交哈希或选择策划分支。
3. 工具校验提交并解析完整 SHA、提交信息、远端分支候选与推送状态；解析期间展示加载反馈。
4. 工具显示三个可编辑字段：代码分支、策划文档分支、提交信息。唯一可信结果自动选中；歧义结果要求人工选择。
5. 用户检查构建摘要并点击“开始构建”；按钮立即禁用以避免重复提交。
6. 工具调用 Jenkins 参数化构建接口，展示排队/运行状态，随后提供构建详情与“在 Jenkins 中打开”。

## Figma 交互

- 入口：Windows 本地工具首页“新建构建”，顶部显示仓库与 Jenkins 连接状态，并提供设置入口。
- 关键页面或弹窗：
  - 空白录入态：代码提交哈希为主输入，策划提交哈希按配置显示为可选输入。
  - 解析完成态：展示提交摘要与三个可编辑构建参数；存在多个分支时使用候选选择框并显示原因。
  - 构建中态：按钮禁用，展示已入队、排队位置或正在运行的阶段反馈。
  - 构建完成态：展示构建编号、结果和 Jenkins 详情链接。
- 关键操作与反馈：粘贴哈希后点击“读取 Git 信息”；解析完成后检查或修改三个参数；点击“开始构建”后防重复提交；成功后打开 Jenkins。
- 空状态：说明可以读取的内容、示例哈希格式和当前仓库配置，不预填可能误导的分支。
- 加载状态：分别显示“正在刷新远端引用”“正在解析提交”“正在提交 Jenkins”“正在等待构建编号”。
- 失败状态：覆盖哈希无效/歧义、仓库不匹配、提交未推送、多分支候选、策划分支无法映射、Git 网络失败、Jenkins 鉴权失败、参数不匹配与触发失败；失败时保留用户已输入内容并提供重试或手工修正。

## 开发备注

- 技术栈或运行环境：建议采用 Python 本地服务读取 Git，浏览器本地界面负责确认参数，Jenkins REST API 负责触发构建；最终技术栈待确认。
- 验证方式：使用两个测试 Git 仓库覆盖唯一分支、多分支、未推送和无效哈希；使用 Jenkins 测试 Job 验证鉴权、参数传递、防重复触发、队列与构建状态。
- 其他约束：Git 命令使用参数数组调用，不拼接 shell 字符串；Token 不写日志；Jenkins 主机与 Job 使用白名单；默认使用 HTTPS 并校验证书。
